# NASA Li-ion Battery Dataset Setup

This project uses lithium-ion battery ageing data from the **NASA Ames Prognostics Center of Excellence (PCoE)** battery dataset.

The raw MATLAB files are intentionally **not stored in this Git repository**.

---

# Dataset Source

Official NASA dataset information:

**NASA Open Data — Li-ion Battery Aging Datasets**

https://data.nasa.gov/dataset/li-ion-battery-aging-datasets

NASA Prognostics Center of Excellence Data Repository:

https://www.nasa.gov/intelligent-systems-division/discovery-and-systems-health/pcoe/pcoe-data-set-repository/

The NASA dataset contains battery ageing experiments involving:

- charge operations,
- discharge operations,
- Electrochemical Impedance Spectroscopy (EIS),
- voltage measurements,
- current measurements,
- temperature measurements,
- capacity degradation,
- and run-to-failure battery ageing trajectories.

The dataset is intended for prognostics research, including Remaining Useful Life estimation.

```text
        ↓

        ↓

```

from the original dataset distribution.

Users should obtain the source files independently from the authoritative NASA source or another source permitted by the dataset provider.

# Dataset Structure

The NASA MATLAB files contain a top-level structure named:

```text
cycle
```

A critical point is that this structure contains **operation records**, not only discharge cycles.

Operations may include:

```text
charge
discharge
impedance
```

Therefore:

> The MATLAB structure index must not automatically be interpreted as battery discharge-cycle number.

This distinction is essential for correct degradation analysis.

---

# Cycle Reconstruction Used in This Repository

The project loader is implemented in:

```text
src/nasa_loader.py
```

It preserves two different indices.

## `record_index`

Represents the original position of the operation record in the NASA MATLAB structure.

Example conceptually:

```text
record_index    type
1               charge
2               discharge
3               impedance
4               charge
5               discharge
...
```

## `discharge_cycle`

Represents the sequential count of discharge events only.

Example:

```text
record_index    type        discharge_cycle
1               charge      -
2               discharge   1
3               impedance   -
4               charge      -
5               discharge   2
...
```

For downstream battery degradation modelling:

```text
cycle = discharge_cycle
```

This reconstructed discharge-cycle index is used for:

- SOH trajectories,
- degradation-rate analysis,
- EOL identification,
- RUL construction,
- chronological feature engineering,
- and model validation.

# State-of-Health Definition

For this project:

\[
SOH_t =
\frac{Q_t}{Q_0}
\times 100
\]

where:

- \(Q_t\) is measured discharge capacity at cycle \(t\),
- \(Q_0\) is initial measured discharge capacity.

The feature is generated by:

```text
src/battery_features.py
```

---

# End-of-Life Definition Used in This Project

The project uses:

```text
SOH <= 80%
```

as the configured modelling EOL threshold.

The observed EOL cycle is defined as the first measured discharge observation satisfying this condition.

For a pre-EOL observation:

\[
RUL_t =
EOL_{cycle} - cycle_t
\]

This is the **project's modelling definition**.

It should not be confused with every possible retirement criterion used in real battery systems.

Applications may use different thresholds depending on:

- chemistry,
- warranty requirements,
- power capability,
- resistance growth,
- safety margin,
- duty cycle,
- second-life requirements,
- or system-level economics.

---

# Important Difference from the NASA Experiment Description

The original NASA experimental description discusses an EOL criterion based on approximately **30% capacity fade from the rated 2 Ah capacity to about 1.4 Ah**.

This repository instead configures its analytical RUL target around:

```text
80% SOH
```

relative to the initial measured discharge capacity used by the project.

The two definitions therefore should not be treated as identical.

The project-specific threshold was selected to demonstrate a common battery-health retirement criterion while keeping the modelling definition explicit and reproducible.

# Production Prognostic Features

The deployed RUL model uses:

```python
[
    "SOH_lag1",
    "SOH_roll_mean_5",
    "SOH_roll_std_5",
    "SOH_delta_5",
    "temp_roll_mean_5",
    "temperature_delta_5",
    "voltage_roll_mean_5",
]
```

These features are designed to summarize historical battery behaviour while avoiding direct use of the current discharge-cycle number as an RUL predictor.

---

# Data Leakage Warning

For this project:

```text
RUL = EOL cycle - current cycle
```

Therefore current cycle number directly participates in construction of the target.

Including:

```text
cycle
```

as an RUL predictor would allow a model to partially reconstruct the target algebraically.

For that reason, cycle number is intentionally excluded from the deployable RUL feature set.

Current SOH and current capacity are also excluded from the RUL predictor set; the deployable features are based on lagged and rolling battery history.

# Dataset Limitations

The four cells used here are laboratory ageing experiments.

They do not independently establish model generalization to:

- commercial EV fleets,
- stationary storage fleets,
- different lithium-ion chemistries,
- different manufacturers,
- different cell formats,
- different temperature distributions,
- dynamic automotive drive cycles,
- pack-level imbalance,
- arbitrary charging protocols,
- field vibration,
- or calendar-ageing-dominated systems.

The resulting models should therefore be interpreted as a **battery prognostics methodology demonstration**, not as a universally calibrated BMS model.
